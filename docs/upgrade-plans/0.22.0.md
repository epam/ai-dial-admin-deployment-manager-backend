# Upgrade Plan — 0.22.0

One breaking change: NVIDIA NIM deployment support is removed. No new variables.

---

## 1. Breaking changes

### 1.1 NIM deployment support removed

- API: deployment type `NIM` (`"$type": "nim"`), source type `ngc_registry`, export component type `NIM_DEPLOYMENT`, and the `nimDeployments` field of the import preview response are removed. Requests using them now return **400**. The admin frontend must drop NIM from its deployment-type lists and filters before or together with this release.
- Data: on first start, migration `V1.60__RemoveNimDeployment` **permanently deletes** all NIM deployments, their topics, audit history and activity-feed entries, and drops the `nim_deployment` / `nim_deployment_aud` tables.
- Export archives created by earlier releases still import; their `nimDeployments` block is ignored.

---

## 2. Before upgrading

**Rolling update.** `V1.60` drops `nim_deployment` while 0.21.x replicas may still be running. Their Hibernate JOINED polymorphic queries on deployments outer-join `nim_deployment` and will error until the rollout completes. Scale to one replica or use the `Recreate` strategy for this upgrade.

The application no longer manages `NIMService` resources, so it cannot remove ones that still exist. On 0.21.x, do the following:

1. Undeploy every NIM deployment through the API/UI (this deletes its `NIMService` cleanly), then verify `kubectl get nimservices -A` returns nothing before upgrading. The migration deletes the `NIM_SERVICE` cleanup-queue rows, so a background delete that failed would not be retried after the upgrade.

If you cannot undeploy them first, leave the `NIMService` resources in place and clean them up manually after upgrading (see section 3).

If you need the NIM deployment definitions for reference, export them via the config export on 0.21.x before upgrading.

---

## 3. After upgrading

- If any `NIMService` resources were left behind, delete them manually:
  ```bash
  kubectl get nimservices -A
  kubectl delete nimservice <name> -n <namespace>
  ```
  and delete any Ingress objects that were created for NIM services in legacy (non-KServe) mode.
- Remove the variables listed under 0.22.0 → Removed in `docs/INFRA-CHANGELOG.md` (optional; they are ignored).
- Remove the `nimservices` Role/RoleBinding from the NIM namespace (optional).
- The NIM Operator and its CRD can be uninstalled if nothing else uses them.

---

## Pre-flight Checklist

- [ ] NIM deployments undeployed and `kubectl get nimservices -A` returns nothing (or leftover `NIMService` resources scheduled for manual deletion after upgrading)
- [ ] Rollout uses a single replica or the `Recreate` strategy
- [ ] NIM deployment definitions exported on 0.21.x if needed for reference
- [ ] Admin frontend updated to drop the NIM deployment type
