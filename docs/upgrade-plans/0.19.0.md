## 2. High-Priority Changes

### 2.1 Container & Build — Auto-provisioned Image Pull Secrets

When enabled, the service auto-provisions a per-deployment `kubernetes.io/dockerconfigjson` pull secret and wires it into the generated workload's `imagePullSecrets` whenever an in-scope image — an image-based deployment's image or a chained inference transformer image — comes from a **credentialed** configured registry (the primary `DOCKER_REGISTRY` or a `BASIC`-auth trusted-private registry). Images from public/unconfigured registries are untouched; the predictor and NIM workloads are out of scope.

> [!IMPORTANT]
> If you previously used the manual workaround — creating a docker pull secret and patching the namespace **ServiceAccount** with a global `imagePullSecrets` entry — **remove that global ServiceAccount pull secret** after upgrading. The manager now provisions per-deployment pull secrets and cleans them up on undeploy; a leftover global SA secret is redundant, keeps stale credentials on the cluster, and can mask registry-scope mistakes.

> [!NOTE]
> Enabled by default (`AUTO_PULL_SECRET_ENABLED=true`) and backward-safe. The auto-provisioned secret is tracked as a disposable `SECRET` resource and cleaned up on undeploy. Set `AUTO_PULL_SECRET_ENABLED=false` only if you want to keep managing pull secrets yourself.


| Setting                    | Default | Required (Yes/No) | Description                                                                                                                                            |
| -------------------------- | ------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `AUTO_PULL_SECRET_ENABLED` | `true`  | No                | Auto-provisions a `dockerconfigjson` pull secret and sets `imagePullSecrets` on generated workloads for in-scope images from a credentialed registry. |


**Helm values.yaml** ([dial-admin chart](https://github.com/epam/ai-dial-helm/tree/main/charts/dial-admin)) — only needed to opt out (default is already `true`):

```yaml
manager:
  env:
    AUTO_PULL_SECRET_ENABLED: "false"
```

## 4. Low-Priority / Optional Changes

### 4.1 Observability — Deployment Metrics Scrape promoted out of Preview

Deployment Metrics Scrape (`GET /api/v1/deployments/{id}/metrics`) is promoted out of **[Preview]** and is now a stable feature.

> [!NOTE]
> No configuration or RBAC changes. The metrics settings keep their existing defaults, and the RBAC requirement is unchanged (read-only `pods/proxy` for INFERENCE engine metrics, plus `metrics.k8s.io` pods when the resource-usage block is enabled).
