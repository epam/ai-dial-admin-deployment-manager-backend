## 2. High-Priority Changes

### 2.1 Security & RBAC — DCGM Exporter Namespace Access for GPU Metrics

| Setting | Default | Required (Yes/No) | Description |
|---|---|---|---|
| DCGM exporter namespace RBAC (`pods`, `pods/proxy` read) | Not granted | Yes, if GPU metrics are wanted (`METRICS_SCRAPE_GPU_ENABLED` defaults to `true`) | A new Role in the DCGM exporter namespace (default `gpu-operator`) is required. None of the four namespaces already documented under **Required Kubernetes RBAC** (build, Knative, NIM, KServe) cover it. Without this Role, GPU metrics silently report "unavailable" — not an error. |

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: dial-deployment-manager-dcgm-reader
  namespace: gpu-operator # matches METRICS_SCRAPE_GPU_DCGM_NAMESPACE
rules:
  - apiGroups: [""]
    resources: ["pods", "pods/proxy"]
    verbs: ["get", "list", "watch"]
```

> [!NOTE]
> Bind this Role to the deployment manager's ServiceAccount via a RoleBinding in the DCGM exporter namespace. If your DCGM exporter runs in a different namespace than `gpu-operator`, set `METRICS_SCRAPE_GPU_DCGM_NAMESPACE` accordingly and target the Role there instead.

## 3. Medium-Priority Changes (defaults changed — review)

### 3.1 Observability — GPU Metrics Scrape Configuration

| Setting | Default | Required (Yes/No) | Description |
|---|---|---|---|
| `METRICS_SCRAPE_GPU_ENABLED` | `true` | No | Enables the per-pod GPU block (utilization + framebuffer memory used/total), sourced from the DCGM exporter, for deployments that request `nvidia.com/gpu`. Degrades gracefully when the exporter is absent. |
| `METRICS_SCRAPE_GPU_DCGM_NAMESPACE` | `gpu-operator` | No | Namespace the DCGM exporter DaemonSet runs in. Set to match your actual install. |
| `METRICS_SCRAPE_GPU_DCGM_POD_SELECTOR` | `app=nvidia-dcgm-exporter` | No | Label selector identifying the DCGM exporter pods. Confirm it matches your exporter's labels. |
| `METRICS_SCRAPE_GPU_DCGM_PORT` | `9400` | No | Port the DCGM exporter serves Prometheus metrics on (standard default). |
| `METRICS_SCRAPE_GPU_DCGM_METRICS_PATH` | `/metrics` | No | HTTP path of the DCGM exporter's Prometheus endpoint. |
| `METRICS_SCRAPE_GPU_DCGM_POD_LABEL` | `pod` | No | DCGM series label carrying the owning pod name. Only change if your DCGM install relabels this series. |
| `METRICS_SCRAPE_GPU_DCGM_NAMESPACE_LABEL` | `namespace` | No | DCGM series label carrying the owning pod's namespace. Only change if relabeled. |
| `METRICS_SCRAPE_TIMEOUT_MS` | `10000` | No | Existing setting — now also bounds each GPU scrape, in addition to engine `/metrics` scrapes. Raise it if GPU-dense nodes start timing out. |

**Helm values.yaml** ([dial-admin chart](https://github.com/epam/ai-dial-helm/tree/main/charts/dial-admin)) — only needed to change from defaults:

```yaml
manager:
  env:
    METRICS_SCRAPE_GPU_ENABLED: "true"
    METRICS_SCRAPE_GPU_DCGM_NAMESPACE: "gpu-operator"
    METRICS_SCRAPE_GPU_DCGM_POD_SELECTOR: "app=nvidia-dcgm-exporter"
    METRICS_SCRAPE_GPU_DCGM_PORT: "9400"
```

## 4. Low-Priority / Optional Changes

- Deployment Metrics Scrape Configuration promoted out of Preview (previously `[Preview] Deployment Metrics Scrape Configuration`) — informational, no action required.
- **Fixed:** NIM progress-deadline annotation now correctly propagates in KServe mode via `NIMService.spec.annotations` instead of `NIMService` metadata, which the NIM operator never forwarded to the underlying `InferenceService`. No RBAC or config change needed — the existing NIM Role's `create` verb already covers this, since the annotation is set at manifest-creation time, not patched afterward. If you were relying on the previous (non-functional) behavior for anything, re-verify progress deadlines on NIM+KServe deployments after upgrading.
