## 1. Medium-Priority Changes (review)

### 1.1 Configuration & API — Resolution Order and Scope Validation

| Setting | Default | Required (Yes/No) | Description |
|---|---|---|---|
| `TRUSTED_PRIVATE_GIT_REPOS` | unset | No | Resolution is most-specific-wins instead of array order. Entries redundant at the same `(host, path, auth type)` scope now fail startup. No action for one-entry-per-host values. |

Duplicate-scope check — no output = nothing to do; each line printed fails startup:

```bash
echo "$TRUSTED_PRIVATE_GIT_REPOS" | jq -r '
  [ .[] as $e
    | ( (if $e.sshKeyPath then ["SSH"] else [] end)
      + (if $e.user then ["HTTPS/HTTP"] else [] end) )[] as $a
    | "\($e.host) | \($e.path // "(domain-wide)") | \($a)" ]
  | group_by(.) | map(select(length > 1)) | .[] | .[0]'
```

Precedence, if two `host` values overlap by parent domain (`example.com` also matches `git.example.com`):

| # | Rule |
|---|---|
| 1 | Exact `host` beats a parent-domain match, regardless of `path` |
| 2 | Among parent-domain matches, longest `host` wins before `path` |
| 3 | Within one `host`: exact repo `path` > prefix `path` > no `path` |

## 2. Low-Priority / Optional Changes

### 2.1 Configuration & API — Scoped Credentials via `path`

| Setting | Default | Required (Yes/No) | Description |
|---|---|---|---|
| `TRUSTED_PRIVATE_GIT_REPOS` | unset | No | Optional `path` per entry scopes a credential to a repository or project/group path under `host`. Omit = `0.20.0` behaviour. `host` is case-insensitive, `path` case-sensitive. |

**Helm `values.yaml`** — `manager.secrets` (rendered via `secretRef`), not `manager.env`: the value holds passwords and tokens.

```yaml
manager:
  secrets:
    TRUSTED_PRIVATE_GIT_REPOS: '[{"host":"git.example.com","path":"team/service-a","user":"user1","token":"repo-token"},{"host":"git.example.com","path":"team","user":"user1","token":"project-token"},{"host":"git.private.com","sshKeyPath":"/path/to/id_rsa","sshKnownHostsPath":"/path/to/known_hosts"}]'
```
